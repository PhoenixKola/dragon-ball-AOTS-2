# Active asset routing

`src/engine/scenes/BootScene.ts` loads battle stills from `src/data/spriteManifest.generated.ts`, existing Goku Kaioken/SSJ frames from `src/data/powerupSprites.generated.ts`, and the authored sequences named by `src/data/battleAnimationFrames.ts`. `ATTACK_FRAMES`, `IDLE_FRAMES`, `POSE_FRAMES`, and `ANIMATION_PROFILE` in that module are the combat animation source of truth.

All **24 combat actor/form identities** have four distinct generated melee drawings and four distinct idle drawings: the five core heroes, Nail, Cui, Dodoria, both Zarbon forms, Guldo, Recoome, Burter, Jeice, Ginyu, Frieza Force soldier, Trunks base/SSJ, Frieza forms 1–5, and Cooler. The five core heroes also have four-frame charge loops and four-frame signature-release sequences. Runtime cuts are in `public/assets/reviewed/actors/`.

Attack playback is 40 fps, nonlooping, and holds its last drawing. Frame 3 is the melee contact pose; clip events begin before the combat engine's hit marker. Idle loops run at 5 fps, charge loops at 8 fps, and special-release sequences at 30 fps. The renderer only displays frames; the combat engine still owns damage and skill VFX. The five signature-release body sequences are actor-specific but shared across that hero's special skills; the existing skill VFX retain move identity.

Each core party member now has a unique four-frame base-form hurt/recovery sequence (`<actor>_hurt_frame_01.png` through `_04.png`). They play at 16 fps for the existing timed hurt reaction; approved stills remain fallbacks, and Goku's Kaioken/SSJ retain their independent routed poses.

Generated contact sheets and per-pose JSON metadata are under `art-sources/production/<actor>/`. `tools/integrate_strike_contact.py <actor> --pose <idle|attack|charge|special|hurt> --cells <four zero-based indices>` cuts supported contact sheets into approved canvases. Runtime/package output excludes `art-sources/` and `evidence/`. `npm run audit:runtime` checks missing files, nonempty alpha, duplicate drawings, canvas dimensions, and foot anchors for all active new sequences.

The nine title/battle backgrounds, dedicated SSJ awakening backdrop, and orbital/shoreline arrival plates load through `BootScene.ts`. The awakening scene uses the final-area ember ambience over `public/assets/backgrounds/awakening_namek.png`; the opening cutscene composites a traveling capsule over `voyage_namek.png`, crossfades to `landing_namek.png`, then waits for an explicit handoff to exploration. Battle encounters continue using their registered location backgrounds. Existing art archives stay untouched because dynamic usage has not been ruled out. Exact actor/form/pose frame counts are listed in [ANIMATION_COVERAGE.csv](ANIMATION_COVERAGE.csv); actor-by-actor acceptance is in [ART_ACCEPTANCE_FINAL.csv](ART_ACCEPTANCE_FINAL.csv).

Four native-generated Namekian field atlases (`namek_trader`, `namek_elder`, `namek_child`, `namek_villager`) are registered by `src/data/overworldNpcArt.generated.ts` and loaded by the shared overworld manifest. Each provides four directions, a fixed 144×144 frame canvas with feet at y=140, one idle drawing and three unique walk drawings per direction. Village trader/healer/child/elder and shoreline fisher use the appropriate new silhouettes; the child is scaled to 58 visible pixels, with adult variants at 78–84 pixels. `tools/cut_overworld_npc_atlas.py` reproduces the cut from the preserved transparent 4×4 source atlas. Legacy collision, coordinates, dialogue and shop scripts remain unchanged.

The Ginyu frog payoff uses a native-generated Namekian frog sprite at `public/assets/reviewed/overworld/namek_frog/right/hop_000.png`. It is a single 144×144 transparent hop cel (56px visible height, foot anchor y=140), prepared from the preserved source by `tools/prepare_overworld_single_sprite.py`; the cutscene animates its hop path and Body Change interception in code. The scene composites the existing reviewed Ginyu and Goku battle stills over the registered Namek water background. This field-only sprite is loaded by `GinyuFrogCutscene.tsx` and does not change combat or collision.

Batch 3 adds a versioned, native image-generated Namek grass texture at `public/assets/world/tex/grass_namek_v2.png`. It is loaded alongside the original grass tile and blended as a low-opacity detail layer; the original source tile remains the base and is available as a fallback. The generated tile has been visually checked in the Azure Shore field capture; it is a texture tile, not a map or collision source.
